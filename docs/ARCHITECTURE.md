# 架构与游戏接入

接手索引：[项目状态](PROJECT_CONTEXT.md) · [待办](TODO.md)。本文件沿用首版架构，补充已落地约束。

## 依赖方向

Web 应用导入游戏 manifest 和平台服务。manifest 仅包含静态信息及动态 import，不应导入规则或运行模块。游戏只依赖 SDK、UI 和自身代码；不能导入平台、Web 应用或其他游戏。

游戏按 `manifest → mount(container, context) → instance` 启动。平台处理加载、保存、页面隐藏暂停和销毁。游戏规则为纯状态转换，渲染是订阅者；禁止规则直接读写数据库、DOM、系统时间（初始化种子除外）或网络。

首版是一个静态应用，没有微前端、远程插件、服务端或共享可变游戏状态。未来游戏引擎可在传入容器内建立 Canvas，遵守相同生命周期；无需重写大厅。

## 接入第四款游戏

1. 新建 `packages/<id>`，使用 workspace 包，依赖 `@game-box/sdk`，React 游戏可依赖 `@game-box/ui`。
2. 定义独立、可序列化的状态和纯规则转换；随机行为接受种子；单独编写规则测试。
3. 实现模块的 `validate(unknown)`、`migrate(unknown, fromVersion)`、`mount(container, context)`。
4. 挂载后立即通过 `context.onChange` 提交初始状态，每次已提交动作后提交新状态；不得提交 DOM、函数、计时器或类实例。胜利调用 `onWin`，运行错误调用 `onError`。
5. 返回实例的 `pause/resume/destroy/snapshot`。暂停后阻止状态变化；销毁解除全部事件、计时器与渲染资源；snapshot 返回独立的可序列化副本。
6. 提供轻量 manifest：稳定 id、名称、简介、cover 字符、游戏版本、存档版本、内容版本、规则说明与动态加载函数。导出 `./manifest`。
7. 在应用 registry 中加入 manifest，并在 Web 应用所在工作区声明包依赖。根工作区目前统一承载前端依赖；无需改动其他游戏。
8. 为新增游戏加入入口、操作、保存恢复、暂停销毁和结算集成测试。

大厅现有三款定制封面是首版视觉资产；新增游戏默认使用 manifest.cover 的基础图标形式，可按需添加专属封面。运行层不依赖游戏 ID。

## 存档与迁移

`SaveRepository` 定义 read、backup、write、remove；当前实现为 `LocalSaves`。写入时先复制快照，再通过串行队列和同一 IndexedDB 事务将旧值放入备份、写入当前值。一次失败不会阻断后续队列。

平台数据库结构版本由 Dexie 管理；每款游戏的 `schemaVersion` 独立。`contentVersion` 用于地图或内容不兼容变更。游戏发布版本不用于判断存档格式。

连连看/蜘蛛仍使用格式 1。魔塔使用格式 2，通过 migrate 将版本 1 快照无损标记为经典旅程；未知格式拒绝。未来修改格式时提升 manifest.saveVersion，并在游戏的 migrate 内逐级转换旧格式，返回新状态；为每个受支持旧版本保存固定测试样本。不要仅修改版本号后接受未知数据。

加载先校验当前内容版本或 manifest 明确声明的 compatibleContentVersions，再运行游戏迁移和校验。未声明兼容的版本仍拒绝；不能为绕过校验随意扩展列表。当前无效时尝试验证备份；用户选择恢复或新开局后，原 current/backup 一并存入 archives，再清空活动槽位。数据库无法归档时不覆盖原数据。没有可用存储时仍能游玩，但显式提示无法保存。

`remove` 是底层能力；产品新开局使用 archiveAndClear 保留数据。归档暂无用户导出界面。云存档可新增 Repository 实现，但身份、冲突解决、离线队列和跨设备同步需在该功能立项时设计，不能仅替换数据库而假定同步完成。

## 魔塔内容

`content.json` 为升级版（内容 2）地图、怪物、物品收益与商店数据，`content-v1.json` 是线上旧版数据的原样快照，禁止修改。地图为 9×9 字符网格，10 层交替方向，带守卫或门控制的捷径；`route` 是可复现的基准通关路线，生产 UI 不使用它。

符号：`#` 墙、`.` 路、`<` 下楼、`>` 上楼、`k` 钥匙、`d` 门、`a/v` 攻击/防御宝石、`p` 药水、`g` 金币、`s` 商店、`m` 怪物、`e` 精英、`B` 最终守卫。

楼梯保存整份入口快照，回退会恢复当时所有楼层地图与勇者属性，防止回退重复获取物品。战斗玩家先攻，伤害为 `(ceil(怪物生命 / 玩家有效攻击) - 1) × 怪物有效攻击`；无法破防或伤害不小于当前生命时不允许战斗。

## 交互与生命周期约束

- `mountReact` 使用独立 React root。销毁先设置 dead 阻止输入，再通过 `queueMicrotask` 卸载，避免宿主 React 提交过程中同步卸载子 root 的警告；不要改回同步卸载。
- 页面隐藏时暂停，返回前台后必须手动继续。`destroy` 必须释放键盘监听、ResizeObserver、定时器等资源；暂停不写入游戏状态。
- 连连看 `path` 仅判断几何可达性，供生成算法复用；`match`/`hint` 另行检查图案相同。不要在 `path` 内增加同图案限制，否则会破坏可解棋盘生成。
- 连连看路径使用消除前棋盘计算，动作与存档立即提交；900ms SVG 反馈、选择、提示标记仅属于 UI，不写入存档。暂停、后续操作及销毁应清理反馈。ResizeObserver 分别测量行距、列距，不能假定二者相等。
- 蜘蛛纸牌历史保存完整局面，撤销必须涵盖翻牌、补发与自动收牌。被后续牌覆盖的按钮只保留 29px 可点击高度，避免牌面重叠拦截点击；窄屏放大在牌桌内滚动，不扩宽页面。

## 实现边界

- 根目录的 `index.html`、Vite 配置和 package.json 负责构建；`apps/web` 当前未独立承载依赖。大部分共享样式仍在 `apps/web/src/style.css`，调整公共选择器需回归三款游戏。
- 注册表与运行契约独立，但大厅前三款封面、标签还有定制展示。新增游戏有默认封面；不要假定所有展示信息已完全由 manifest 驱动。
- `Settings` 目前仅传递系统 reducedMotion 偏好，无用户设置持久化或设置页面。
- 本地队列保证单实例写入顺序，不提供多标签页冲突协调；归档恢复通过平台扩展方法实现，不属于基础 SaveRepository 接口。扩大存档能力前先复核这些边界。

## 魔塔体验升级与兼容（2026-09-28）

- manifest.saveVersion/contentVersion 均为 2，兼容内容版本 1。migrate(旧格式, 1) 给当前状态和 checkpoint 添加 campaignVersion: 1，其余数据不变；保存后外层 envelope 为 2，旅程内部仍使用经典数值。新游戏 campaignVersion: 2，重开前沿用平台确认与归档。
- `floorFor` / `itemsFor` 按旅程版本获取数据；读取怪物、商店、楼梯位置均必须走该分派，不能让旧存档读取新配置。`floors` 导出仅代表新内容，主要供基准路线测试使用。checkpoint 与当前状态的 campaignVersion 必须一致。
- `battlePreview` 与实际战斗共用 damage；展示回合、反击、预计损失、战后生命及阻止原因。地图点选、详情选择、图例展开是 UI 临时状态；点选不能移动、战斗或存档。
- 精英通道用较大生命代价交换更多金币及路线选择；额外钥匙支持捷径/保留取舍；不同属性价格由 shop.costs 控制，旧版退回统一 shop.cost。固定测试验证逐层攻击投资和防御投资都可通关，后续数值调整需维持已验证路线或提供新的明确通关方案。
- `tests/fixtures/tower-v1.json` 是不带新字段的旧格式固定样本；保留迁移、再次加载、回退及新开局切换测试。不得将样本升级到新格式后继续称其为迁移测试。旧应用不识别新格式，发布后勿直接回滚到仅支持格式 1 的代码。
